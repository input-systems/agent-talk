# Contributing

Thank you for helping with Agent Talk.

- **Specification changes** start as an issue that says what problem the change solves and which rule or section it touches. Changes stay additive within version 1 (section 12 of the protocol); a change in meaning takes a new version.
- **Implementation changes** keep the reference implementation free of runtime dependencies, keep verifying and checking fail-closed (never throwing), and come with tests.
- **Test vectors** are generated by `pnpm vectors:generate` and checked by `spec/vectors/vectors.test.ts`. A change that alters a vector needs a reason in the pull request.

Before opening a pull request, run:

```sh
pnpm install
pnpm check
pnpm test
```
